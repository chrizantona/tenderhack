# Wildberries MVP data access research

Дата проверки: 2026-05-20.

## Краткий вывод

Самый быстрый MVP-способ: публичный JSON endpoint поиска `u-search.wb.ru/exactmatch/ru/common/v18/search` плюс нормализация полей из ответа.

Самый надежный для карточки по известному товару: ручной nmID/URL и публичный `wbbasket` JSON `info/ru/card.json`; он хорошо дает характеристики, описание, медиа и brand, но не текущую витринную цену.

Не стоит использовать как основной путь: HTML-парсинг страниц `www.wildberries.ru`. При проверке обычный `curl` получил antibot/JS challenge вместо выдачи и карточки.

## Таблица способов

| Способ | Что получает | Сложность | Стабильность | Риски | Рекомендация |
|---|---|---:|---:|---|---|
| `u-search.wb.ru/.../v18/search` | Список товаров по текстовому запросу: nmID, название, бренд, цена, старая цена, рейтинг, отзывы, продавец, наличие, subject, colors, количество фото | Низкая | Средняя | Неофициальный endpoint, может смениться версия/схема, возможны `429` | Лучший старт для хакатона |
| `wbbasket` `info/ru/card.json` по nmID | Детальная карточка: характеристики, описание, категория, brand, цвета, количество фото/video, vendor code | Средняя | Средняя | Нужно определить basket host; нет текущей витринной цены/остатков | Использовать для enrichment по найденным nmID |
| `wbbasket` `price-history.json` по nmID | История цены в RUB | Низкая | Средняя | Это история, не гарантированная текущая цена оффера | Использовать только как fallback/контекст |
| `card.wb.ru/cards/v4/detail` по nmID | Частично карточка: seller, rating, reviews, media; при проверке price/stock не пришли | Низкая | Низкая-средняя | Неполный ответ, отличается от поиска | Можно пробовать как fallback |
| HTML search/card pages | Теоретически выдача/карточка | Средняя | Низкая | При проверке отдается antibot/JS challenge | Не использовать в MVP |
| Playwright/Selenium | Может открыть сайт как браузер и увидеть сетевые запросы | Средняя-высокая | Низкая | Challenge, ToS-риск, нестабильно, дорого | Только ручная отладка, не runtime |
| Ручной URL/nmID | Пользователь вставляет ссылку или nmID, далее `wbbasket` enrichment | Низкая | Средняя-высокая | Нет глобального поиска, цена неполная без search context | Хороший fallback для демо |
| Официальный seller API | Товары/цены/остатки продавца с токеном | Средняя | Высокая | Не дает глобальную покупательскую выдачу | Не закрывает текущий use case |

## Доступные поля

Поиск `u-search`:
- есть: `external_id`, `title`, `brand`, `price`, `old_price`, `rating`, `reviews_count`, `seller`, `availability`, `url`, частично `characteristics`;
- фото можно построить после определения `wbbasket` host;
- характеристики ограничены короткими полями из выдачи.

Карточка `wbbasket`:
- есть: полные характеристики, описание, category/subject, brand, vendor code, количество фото, видео-флаг;
- нет: актуальная витринная цена, старая цена, точные остатки по региону.

## Код PoC

Поиск:

```bash
python3 scripts/wb_search.py "iphone 15 128gb" --limit 5 --enrich-details
```

Карточка по nmID или URL:

```bash
python3 scripts/wb_product.py 825188792
python3 scripts/wb_product.py "https://www.wildberries.ru/catalog/825188792/detail.aspx"
```

Зависимость:

```bash
python3 -m pip install -r requirements.txt
```

## Ограничения

- Endpoint `u-search` неофициальный: версия `v18` и параметры могут измениться.
- `dest` влияет на цену, наличие и доставку. Для сравнения маркетплейсов нужно фиксировать регион.
- При большом числе запросов возможны `429` и временные блокировки.
- `wbbasket` host определяется перебором кандидатов; это нормально для единичных nmID, но нужно кэшировать.
- `price-history.json` не равен текущей цене карточки.
- Нельзя обходить captcha/challenge, использовать proxy pools, украденные токены, приватные аккаунты или агрессивный crawling.

Минимальные лимиты для MVP:
- поиск: 1-2 страницы на запрос;
- enrichment: 5-20 товаров на запрос;
- задержка: 0.2-1.0 секунды между карточками;
- кэш поиска: 10-30 минут;
- кэш `card.json`: 12-24 часа;
- кэш basket host для nmID: бессрочно или до ошибки.

## Рекомендуемые лимиты запросов

Фактический долгий потолок RPS не измерялся намеренно: для хакатонного прототипа не стоит делать нагрузочный тест по неофициальным endpoint'ам WB. Ниже безопасные стартовые лимиты и результат короткого controlled probe.

| Endpoint | Когда дергать | Стартовый лимит для MVP | Кэш | Комментарий |
|---|---|---:|---|---|
| `u-search.wb.ru/exactmatch/ru/common/v18/search` | Поиск по текстовому запросу | 3-5 req/sec sustained, burst до 8 req/sec | 10-30 минут по ключу `query + page + sort + dest` | Основной запрос. Делать debounce ввода 500-800 мс, искать только после submit, не на каждый keypress |
| `wbbasket.../info/ru/card.json` | Обогащение найденных nmID характеристиками | 3-5 req/sec sustained, burst до 8 req/sec | 12-24 часа по `nmID` | Дергать только top N, например 10-20 товаров. Не обогащать всю выдачу |
| `wbbasket.../info/price-history.json` | История цены по nmID | до 1 req/sec, только по требованию | 12-24 часа | Не нужен для каждой выдачи; это не текущая цена |
| `card.wb.ru/cards/v4/detail` | Fallback по nmID | до 0.5-1 req/sec | 5-15 минут | Ответ может быть неполным; при пустой цене не ретраить агрессивно |
| `www.wildberries.ru` HTML | Не использовать | 0 req/sec | нет | При проверке вернул antibot/JS challenge |
| Playwright/Selenium | Только ручная диагностика | не использовать в runtime | нет | Не строить MVP-парсер на браузере |

Короткий probe от 2026-05-20:

| Target | Проверенные уровни | Результат |
|---|---|---|
| `u-search` | 1, 2, 4, 6 RPS по 5 секунд | 65/65 ответов `200`, без `429`; p50 на 6 RPS около 128 мс, p95 около 469 мс |
| `u-search` | 8 RPS на 5 секунд | 40/40 ответов `200`, без `429`; p50 около 155 мс, p95 около 663 мс |
| `u-search` | 10 RPS на 5 секунд | 43 ответа `200`, 7 ответов `429`; это уже слишком близко к лимиту |
| `wbbasket card.json` | 1, 2, 4, 6, 8 RPS по 5 секунд | 105/105 ответов `200`, без `429`; p50 около 90-94 мс на 4-8 RPS |

Практический вывод: для одного инстанса MVP можно поднять лимиты выше первоначально осторожных значений, но не ставить `u-search` выше 5 RPS sustained. Для демо-сценария нормальный паттерн: `1 search request + enrichment 10 товаров` с общей очередью enrichment на 3-5 RPS. Burst до 8 RPS допустим по короткому тесту, но при первом `429` нужно сразу снижать скорость.

Что важно в реализации:
- ставить `timeout` 5-15 секунд и общий лимит времени на enrichment;
- при `429` сразу останавливать запросы к этому endpoint'у и включать backoff 5-15 минут;
- при `5xx` делать максимум 1 retry с экспоненциальной задержкой;
- при ошибке `wbbasket` enrichment не падать всем поиском, а вернуть товар с базовыми полями из `u-search`;
- не перебирать все 45 `basket-*` хостов для каждого товара в горячем пути без лимита. Для MVP: кешировать найденный host, ограничить discovery top-кандидатами или выполнять enrichment в фоне;
- ограничить глубину: `page <= 2`, `limit <= 20`, минимальная длина запроса 3 символа.

Probe-скрипт:

```bash
python3 scripts/wb_rate_probe.py --target search --levels 1,2,4,6 --seconds 5 --stop-on-429
python3 scripts/wb_rate_probe.py --target search --levels 8,10 --seconds 5 --stop-on-429
python3 scripts/wb_rate_probe.py --target basket --levels 1,2,4,6,8 --seconds 5 --stop-on-429
```

## Следующие шаги

- Сделать интерфейс адаптера: `search(query) -> list[Product]`, `get_product(external_id) -> Product`.
- Для Ozon/YandexMarket начать с официальных seller/partner API и ручного URL/nmID fallback; глобальный поиск без партнерского доступа отдельно пометить как риск.
- Нормализация: единая валюта, цена в RUB, `external_id`, URL, seller, rating, reviews, availability, raw source.
- Матчинг: нормализовать brand/title, выделять модель, память, цвет, размер; использовать exact rules для артикулов/моделей и fuzzy/embedding score для остального.
- Для production искать партнерские API, товарные фиды, affiliate/ads data feeds или лицензированные источники данных.
